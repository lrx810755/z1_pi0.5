# Z1 饮料瓶抓取与软件强停工作记录（2026-08-11）

## 本轮目标与当前结论

- 为任务 GUI 增加可随时触发的软件“强制停止抓取”，并让后端真正取消抓取、
  机械臂和夹爪动作，而不是只停止前端等待。
- 继续排查饮料瓶水平侧夹时的 X/Y 耦合与过早微调问题。
- 当前代码、单元测试和 ROS 2 构建均已通过；但尚未完成一轮饮料瓶真实双指接触、
  无 ATTACH 试抬、搬运和释放的端到端成功验证。因此当前失败回合**不得用于训练，
  也不得记作饮料瓶抓取成功**。

## 软件强制停止抓取

- 前端新增红色“强制停止抓取”按钮及二次确认，接口为
  `POST /api/force_stop`。
- GUI 后端同时调用 `/smolvla/stop_assistant` 和 `/smolvla/stop_motion`；强停事件
  可中断服务等待、分段对中、场景等待和慢速闭爪循环。
- 抓取助手会取消当前机械臂动作、普通夹爪动作和持续夹紧动作，清空已批准规划与
  当前候选，并把目标物体恢复为动态物理，避免失败后遗留冻结物体。
- 轨迹桥停止后读取实际关节位置并原地保持，不再返回 home 或上一轨迹段起点，
  避免“急停”本身产生二次运动。
- 自动示教在强停后标记为 `STOPPED`，清理未完成录制；完成 Episode 复位后才清除
  强停锁存并允许新一轮抓取。
- 这是软件级停止，不替代真实机械臂的硬件急停。

## TF 警告结论

- 曾出现 `Lookup would require extrapolation into the future`：物体消息时间戳比
  最新 `world -> gripperStator` TF 快约 16–33 ms。
- 判定器已经回退到最新可用 TF，因此该警告反映仿真时钟/发布周期的轻微不同步，
  不是本轮饮料瓶 X/Y 极限循环的直接原因。
- 仍应避免重复启动 ROS 2/Isaac 进程；多套 `/clock`、TF 或桥节点并存会造成比该
  限频警告更严重的时间回跳与状态冲突。

## 饮料瓶失败的实测原因

- 失败回合进入真实碰撞分段接近时，局部位置从约
  `(0.2178, -0.0064, 0.0216) m` 开始。
- 一次轴向前伸曾把 X 从约 `0.188 m` 推进到 `0.180 m`，同时产生约
  `+4.5 mm` 的 Y 漂移；随后独立 Y 修正又把 X 拉回约 `0.188 m`。
- 后续在 `X≈0.188 m, Y≈0.0047 m` 与
  `X≈0.180 m, Y≈0.0092 m` 之间重复切换，直到耗尽分段预算。增加循环次数或
  单纯放宽成功包络都不能解决该问题。
- 根因是两项控制逻辑叠加：远离瓶身时就启用 Y/Z 精细对中；已经测得的 X/Y
  耦合又会被下一次略低于检测比例的样本覆盖，从而重新退化为交替修 X、修 Y。
- 后续仿真画面仍显示夹爪位于瓶身外侧；一次新回合在局部
  `X≈0.1677 m, Y≈-0.0154 m, Z≈0.0162 m` 就开始近水平姿态转换，并以
  `MoveIt error_code=99999` 失败，进一步证明姿态转换和微调入口仍过早。

## 已实施的控制修正

- 增加饮料瓶专属的粗前伸/微调分界。局部 X 随夹爪前伸而减小：
  - `X > 0.155 m`：只允许轴向 X 粗前伸，禁止 Y/Z 微调抢占轴向运动。
  - `X <= 0.155 m`：才启用 Y/Z 精细闭环对中。
  - `X <= 0.145 m`：才开始分段切换到近水平侧夹姿态。
  - 最终动态插入停止深度仍为 `X=0.125 m`，目标中心仍为 `X=0.117 m`。
- 微调入口具有锁存语义：一旦进入近区，即使横向修正使测得 X 短暂向外变化，
  也不会重新退回粗接近状态。
- X/Y 耦合检测同样改为锁存：在当前 IK 分支上观察到一次有效耦合后，不会因为
  后续单个样本略低于比例阈值而遗忘；需要修 Y 时使用有界联合 X/Y 目标，避免
  纯 Y 运动撤销已经取得的 X 前伸量。
- 饮料瓶当前保持 `roll=-90°`，初始接近仰角 `25°`，近水平姿态按
  `20° -> 15° -> 12°` 分段转换。
