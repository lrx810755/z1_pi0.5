Z1 SmolVLA 下载仓库后的复现指南

Isaac Sim + ROS 2 + MoveIt 2 + LeRobot/SmolVLA
文档版本：V1.0
适用仓库：z1-smolvla
环境基线：Ubuntu 22.04 / ROS 2 Humble / Isaac Sim 5.1.0
更新日期：2026 年 8 月 31 日

文档说明

项目说明
目标读者已下载或收到 z1-smolvla 仓库，需要在另一台 PC 上恢复仿真、数据管线与 SmolVLA 训练环境的使用者。
复现范围压缩包解压、路径配置、ROS 2 构建、Python/训练环境、URDF/USD 重建、数据恢复、系统启动与验收。
不随仓库提供操作系统、NVIDIA 驱动、CUDA 运行能力、ROS 2、MoveIt 2、Isaac Sim、基础 SmolVLA checkpoint、正式训练数据及 Unitree 真机 SDK。
关键原则仓库可放在任意目录；不要手工替换生成文件中的旧绝对路径；目标 PC 上通过脚本重新生成派生资产。
重要：本指南将“代码/资产复现”和“训练结果复现”区分开。完成仓库构建并不代表能得到相同模型；训练结果还依赖同一数据版本、基础 checkpoint、训练参数、随机种子、CUDA/PyTorch 版本和评估协议。

1. 仓库内容与目录结构

目录或入口功能
ros2_ws/src/z1_ros2/Z1 描述、MoveIt 配置、ROS 2 控制桥、抓取与录制节点。
isaac_assets/z1/Isaac USD、扫描物体、场景构建、相机和仿真运行脚本。
lerobot/仓库固定的 LeRobot/SmolVLA 源代码。
dataset/Episode 录制和 LeRobot 数据转换入口。
scripts/环境初始化、ROS 构建、资产重建、验证和打包脚本。
data/runtime/默认本地数据位置；不包含在核心迁移包中。

顶层的 robot_description、simulation、ros2_control、grasping、teleoperation、training 和 tests 多数为相对软链接，用于提供清晰的模块入口。不要将其复制为重复目录。

2. 目标 PC 要求

项目推荐基线与确认方法
操作系统Ubuntu 22.04 x86_64；执行 lsb_release -a 确认。
GPUNVIDIA RTX 4090 级别，至少满足 Isaac Sim 与训练显存要求；执行 nvidia-smi -L。
ROS 2Humble；执行 test -f /opt/ros/humble/setup.bash。
运动规划与 ROS Humble 配套的 MoveIt 2；执行 ros2 pkg prefix moveit_ros_move_group。
Isaac Sim5.1.0，默认安装到 $HOME/isaac-sim；检查对应目录下的 python.sh。
PythonConda Python 3.10；执行 python --version。
磁盘除仓库外，为 Isaac、Conda、数据和 checkpoint 预留足够空间；执行 df -h。

2.1 开始前检查

nvidia-smi -L
test -f /opt/ros/humble/setup.bash && echo "ROS Humble: OK"
test -x "$HOME/isaac-sim/python.sh" && echo "Isaac Sim: OK"
conda --version
df -h

任一关键检查失败时，先修复驱动或系统依赖，不要继续训练。Isaac Sim 能启动也不等同于 PyTorch CUDA 可用，两者都必须单独确认。

3. 解压仓库

交付物只有一个 z1-smolvla-core-YYYY-MM-DD.tar.zst。把它复制到目标 PC 的工作目录后执行：

tar -I zstd -xf z1-smolvla-core-YYYY-MM-DD.tar.zst
cd z1-smolvla

压缩包内部已经包含顶层 z1-smolvla/ 目录，因此不需要预先创建目录，也不需要 GitHub、Git clone 或 Git submodule。

3.1 不应从源 PC 直接复制的本机产物

  • ros2_ws/build/、ros2_ws/install/、ros2_ws/log/：包含本机构建路径，必须在目标 PC 重建。
  • data/runtime/、checkpoint、W&B 输出：需要单独归档和版本管理。
  • Conda 环境目录和 Isaac Sim 安装目录：不应随仓库直接复制。

4. 初始化便携路径

cd /path/to/z1-smolvla
source scripts/setup_env.sh
./scripts/verify_reproduction.sh

脚本默认得到以下变量：

变量默认值作用
Z1_SMOLVLA_ROOT当前仓库根目录所有内部路径的根。
Z1_ASSET_ROOT$Z1_SMOLVLA_ROOT/isaac_assets/z1Isaac 资产与脚本。
Z1_ROS_WS$Z1_SMOLVLA_ROOT/ros2_wsROS 2 工作空间。
SMOLVLA_DATA_ROOT$Z1_SMOLVLA_ROOT/data/runtime录制、审核和转换后的数据。
ISAAC_SIM_ROOT$HOME/isaac-simIsaac Sim 安装位置。
ROS_DISTROhumbleROS 2 发行版。

外部软件或数据位于其他路径时，应在 source 前覆盖变量：

export ISAAC_SIM_ROOT=/opt/isaac-sim
export SMOLVLA_DATA_ROOT=/data/z1-smolvla
source scripts/setup_env.sh
./scripts/verify_reproduction.sh
预期结果：输出 Portable source checks passed.，并显示当前仓库、ROS、Isaac 资产、数据和 Isaac Sim 的实际路径。

5. 构建 ROS 2 工作空间

确保已安装 ROS 2 Humble、MoveIt 2、rosdep、colcon 和必要系统包，然后执行：

source scripts/setup_env.sh
./scripts/bootstrap_ros.sh
source "${Z1_ROS_WS}/install/setup.bash"

脚本默认构建 z1_description、z1_examples、z1_moveit 和 z1_isaac_bridge。它会设置 PYTHONNOUSERSITE=1，避免用户目录中的 setuptools/packaging 污染 ROS 构建。

真机例外：z1_hardware_interface 和 z1_bringup 默认不构建，因为真机接口需要额外的 Unitree SDK/controller、网络配置和版本固定。仿真复现不依赖它们。

5.1 ROS 构建验证

source "/opt/ros/${ROS_DISTRO}/setup.bash"
source "${Z1_ROS_WS}/install/setup.bash"
ros2 pkg prefix z1_description
ros2 pkg prefix z1_moveit
ros2 pkg prefix z1_isaac_bridge
ros2 launch z1_isaac_bridge z1_isaac.launch.py --show-args

6. 创建 SmolVLA 训练环境

conda env create -f environment.yml
conda activate z1-smolvla

根据目标 PC 的 NVIDIA 驱动选择兼容的 CUDA PyTorch。不要盲目复制源 PC 的 CUDA wheel。安装并验证 PyTorch 后，在仓库根目录安装固定的 LeRobot 源码：

# 按 PyTorch 官方说明安装与本机驱动兼容的 CUDA 版本
python -c 'import torch; print(torch.__version__, torch.cuda.is_available())'

python -m pip install -r requirements-training.txt
lerobot-train --help
训练前硬性条件：torch.cuda.is_available() 必须返回 True。如果为 False，先检查驱动、PyTorch wheel 和 CUDA 兼容性。

7. 恢复训练数据与 checkpoint

7.1 数据目录建议

${SMOLVLA_DATA_ROOT}/
├── raw/          # 原始录制，只读保全
├── quarantine/   # 失败或不完整回合
├── reviewed/     # 人工审核通过的数据
└── lerobot/      # 转换后的 LeRobot 数据集

历史完整归档可能包含失败回合、隔离数据和 .recording_* 临时目录。正式训练只能使用人工审核后的版本，禁止将完整归档直接作为训练集。

7.2 转换为 LeRobot 数据集

python "${Z1_ASSET_ROOT}/scripts/export_z1_lerobot_dataset.py" \
  --input "${SMOLVLA_DATA_ROOT}/reviewed" \
  --output "${SMOLVLA_DATA_ROOT}/lerobot/z1_tabletop_v1" \
  --repo-id lp531/z1_smolvla_tabletop

转换后至少记录：原始数据归档名称、审核规则、Episode 数量、成功/失败分布、相机分辨率、语言指令集合以及所用核心压缩包日期。

7.3 checkpoint

基础 SmolVLA checkpoint 不在核心压缩包内。应单独下载或迁移，并记录来源、版本、文件名和授权信息。训练输出也应与核心压缩包分开保存。

8. 重建 URDF 与 USD 派生资产

source scripts/setup_env.sh
source "/opt/ros/${ROS_DISTRO}/setup.bash"
source "${Z1_ROS_WS}/install/setup.bash"
./scripts/rebuild_generated_assets.sh

该脚本依次执行：

  1. 从 Xacro 展开双相机 Z1 URDF；
  2. 规范化扫描物体资产；
  3. 生成带绝对网格解析路径的临时 resolved URDF；
  4. 通过 Isaac Sim 重新导入机器人 USD；
  5. 生成双腕部相机场景和相对路径元数据；
  6. 执行场景与相机 smoke test。

resolved URDF 中出现当前目标 PC 的绝对网格路径是正常现象，它属于派生输入，不是需要手工维护的源码。路径变化、Xacro/网格/相机修改或首次迁移后都必须重建。

脚本默认要求 nvidia-smi -L 成功。只有在明确接受“未完成 GPU 验证”的情况下，才可设置：

Z1_ALLOW_NO_GPU=1 ./scripts/rebuild_generated_assets.sh

9. 启动完整系统

cd /path/to/z1-smolvla
source scripts/setup_env.sh
source "/opt/ros/${ROS_DISTRO}/setup.bash"
source "${Z1_ROS_WS}/install/setup.bash"
ros2 launch z1_isaac_bridge z1_isaac.launch.py

临时覆盖 Isaac 或数据位置：

ros2 launch z1_isaac_bridge z1_isaac.launch.py \
  isaac_sim_root:="${ISAAC_SIM_ROOT}" \
  dataset_root:="${SMOLVLA_DATA_ROOT}/z1_tabletop_raw_dual_wrist"

11. 开始正式训练前必须固化的信息

当前仓库提供 LeRobot/SmolVLA 训练入口，但尚未固化项目专用的一键正式训练配置。因此正式训练前应创建并版本化一份实验清单，至少包含：

  • 核心压缩包文件名和日期；LeRobot 版本；基础 checkpoint 名称与版本；
  • 数据集名称、版本、路径、Episode 数和审核规则；
  • 训练命令的完整参数：batch size、学习率、步数、保存间隔、图像键、状态键、动作维度；
  • 随机种子、GPU 型号、驱动、CUDA、PyTorch 和 Transformers 版本；
  • 评估任务、成功判据、seed 列表和每个 checkpoint 的成功率。

先通过 lerobot-train --help 确认当前固定版本的参数名称，不要直接套用其他版本教程中的命令。

12. 常见问题排查

现象原因与处理
Portable source checks 失败确认在仓库根目录执行；检查仓库是否完整、软链接是否保留，以及是否自行加入了机器绝对路径。
ROS 构建出现 setuptools/packaging 冲突使用 scripts/bootstrap_ros.sh；该脚本已设置 PYTHONNOUSERSITE=1。不要让 ~/.local Python 包覆盖 ROS 系统环境。
找不到 Isaac python.sh在 source 前设置正确的 ISAAC_SIM_ROOT。
Isaac 报 No space left on device，但磁盘有空间通常是 inotify 实例上限。检查 cat /proc/sys/fs/inotify/max_user_instances，由系统管理员按需提高。
Isaac 报无 CUDA/Vulkan 设备先保证 nvidia-smi -L 正常，再检查显示会话、容器 GPU 映射和驱动兼容性。
torch.cuda.is_available() 为 False安装与目标驱动兼容的 CUDA PyTorch；不要只依赖系统中存在 CUDA toolkit。
resolved URDF 出现旧 PC 路径不要手工替换。删除对旧派生物的依赖并重新运行 scripts/rebuild_generated_assets.sh。
话题有名称但没有数据检查 Isaac ROS bridge、RMW_IMPLEMENTATION、ROS_DOMAIN_ID、仿真是否播放及发布频率。
训练结果无法复现核对数据集和 checkpoint 的名称与版本、完整训练参数、随机种子、依赖版本和评估协议。

13. 最短执行流程

# 1. 仓库与路径
cd /path/to/z1-smolvla
source scripts/setup_env.sh
./scripts/verify_reproduction.sh

# 2. ROS
./scripts/bootstrap_ros.sh
source "/opt/ros/${ROS_DISTRO}/setup.bash"
source "${Z1_ROS_WS}/install/setup.bash"

# 3. Python/SmolVLA
conda env create -f environment.yml
conda activate z1-smolvla
# 安装与本机驱动兼容的 CUDA PyTorch
python -m pip install -r requirements-training.txt
python -c 'import torch; print(torch.cuda.is_available())'

# 4. 恢复数据与基础 checkpoint 后重建资产
./scripts/rebuild_generated_assets.sh

# 5. 启动
ros2 launch z1_isaac_bridge z1_isaac.launch.py
