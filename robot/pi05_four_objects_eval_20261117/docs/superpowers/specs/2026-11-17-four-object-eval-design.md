# 本轮四物体评估接口

目标：为用户手动启动最终 PI0.5 LoRA 仿真评估准备接口。本次不启动场景、GPU推理或闭环评估。

约束：训练数据1762条及训练参数不变；仅允许本轮800000微步/100000次更新检查点；最终完成标记、最新检查点、模型配置和处理器均须核对，不能回退95000次模型。正式运行还须对应最终模型重载验证通过。

方案：复用现有ROS评估运行时的独立快照，移除该快照中的瓶子专用参数限制；保留原执行、安全停止和物理成功判据。直接改共享入口会影响旧实验，另写执行器会重复已有物理和同步逻辑，因此采用独立快照。新Python入口提供check、dry-run、scene、run和verify-model模式，SH清理并配置环境。默认只检查。

四类：apple、peach、cup、beverage_bottle（接受bottle别名）；任务原文来自冻结清单。输入7维连续状态和原尺寸三路RGB；保存的处理器负责补边224和分位数归一化。预测30步、执行15步、10Hz，命令60Hz插值、flow10步。二值夹爪沿用现有0.4/0.6滞回，开-0.9/闭0rad，默认不增加最短闭爪保持时间。

场景配置取桃子采集配置（同时含苹果1.1、桃子1.2尺寸），独立复制；杯/瓶参数与选定来源核对。使用独立ROS域168，GUI端口8868，场景单独手动启动；不复用其他域的场景。冻结清单提供所有训练种子，覆盖单元由实际源summary坐标按运行时网格计算；新布局排除所有训练种子，不强制距离示范3cm。支持固定新seed并拒绝训练seed。

结果：逐条原有result/trace/input_sync/prediction与三视角视频，分物体报告；追加阶段证据汇总（闭爪、双侧接触、抬升、搬运、释放、任务成功），无证据项明确未知。成功沿用物理放置稳定task_success，不把接触或训练loss当成功。

验证：最终模型未完成时check返回明确未就绪且不导入GPU；CPU检查真实原图与保存处理器、四任务文本、夹爪反归一化及命令解析；故障测试阻止中间检查点、训练种子、缺失/更改工件。GPU无法访问时保留明确的最终重载入口并记录未执行。
