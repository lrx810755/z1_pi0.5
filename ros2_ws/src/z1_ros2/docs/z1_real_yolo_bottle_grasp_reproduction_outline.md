# Z1 实机基于 YOLO 的瓶子识别与抓取复现指南（大纲）

## 1. 文档目标与适用范围

- 最终目标：识别直立瓶子并完成 `approach -> grasp -> home -> release`。
- 适用硬件：
  - Unitree Z1 六轴机械臂；
  - Z1 原装夹爪；
  - 腕部 Intel RealSense D435i。
- 前置条件：
  - 已安装 ROS 2 Humble；
  - 已有能够控制 Z1 实机的 ROS 2 工作区。
- 明确本文不覆盖的内容，例如 ROS 2 和 Z1 SDK 的基础安装。

## 2. 系统架构与数据流

完整数据链如下：

```text
RealSense RGB
    ↓
YOLO bottle 检测
    ↓
检测框中心像素
    ↓
对齐深度 + CameraInfo
    ↓
相机坐标系三维点
    ↓
手眼标定 + TF
    ↓
link00 下的瓶体位置
    ↓
生成水平接近位姿与补偿
    ↓
MoveIt 规划、审核、执行
    ↓
夹爪闭合
    ↓
返回 HOME
    ↓
释放瓶子
```

- 列出使用的话题和 Action。
- 说明相关 TF 坐标系及其关系。

## 13. 一键抓取状态机

### 13.1 Approach

- 获取最新图像和深度。
- 使用 YOLO 识别目标。
- 执行三维定位与坐标转换。
- 生成抓取位姿。
- 调用 MoveIt 规划。
- 保持夹爪张开并执行接近轨迹。

### 13.2 Grasp

- 夹爪闭合到设定角度。
- 闭合速度和等待时间。
- 判断闭合命令是否完成。
- 说明当前系统是否具有真实抓取成功反馈。

### 13.3 Home

- 返回预定义 HOME 位姿。
- HOME 轨迹稳定性判断。
- MoveIt 超时但机械臂实际已经稳定到位时的处理逻辑。

### 13.4 Release

- 张开夹爪。
- 完成状态机。
- 说明中途失败后允许从哪个阶段继续。

## 14. 标准启动与操作步骤

1. 检查硬件、急停和工作区域。
2. 接通 Z1 并确认网络连接。
3. 连接 RealSense。
4. 加载 ROS 2 和工作区环境。
5. 检查标定 YAML 与 YOLO 权重。
6. 启动完整实机 launch。
7. 检查控制器、相机、TF 和 MoveGroup。
8. 在 GUI 中选择 YOLO、模型和 `bottle` 类别。
9. 先执行只识别、不运动的检查。
10. 规划接近轨迹并审核目标。
11. 低速执行完整抓取流程。
12. 保存终端日志和抓取结果。

> 不要同时启动第二套相机、MoveIt 或 Z1 控制器。

## 16. 分阶段复现与验收

不要直接从一键抓取开始，推荐按以下顺序验收：

1. 测试 Z1 HOME 和夹爪开合。
2. 确认 RealSense 连续发布。
3. 确认 YOLO 能稳定识别瓶子。
4. 确认深度与 RGB 对齐。
5. 输出并检查瓶子相机坐标。
6. 输出并检查瓶子 `link00` 坐标。
7. 在 RViz 中验证目标点。
8. 只规划、不执行。
9. 无瓶空跑接近轨迹。
10. 有瓶低速接近但不闭爪。
11. 单独测试夹爪闭合。
12. 完整执行抓取状态机。

每一级都应给出明确的通过标准。

## 17. 常见故障诊断

按“现象 -> 检查命令 -> 原因 -> 解决方法”的格式覆盖：

- YOLO 依赖未安装。
- 模型无法加载或无法联网下载。
- 找不到 `bottle` 类别。
- RealSense 未发现或中途断流。
- GUI 有画面，但规划节点一直等待 RGB。
- 深度为零或透明瓶深度不可靠。
- CameraInfo 与图像分辨率不匹配。
- TF 不存在、方向错误或时间外推。
- 手眼标定造成固定方向偏差。
- MoveIt 无 IK 解。
- 起始状态超差。
- joint6 约束过紧。
- 抓取点正确但夹爪 stator 撞瓶。
- 远距离闭爪时将瓶子推出夹持区域。
- HOME 返回超时。
- 重复启动控制器、相机或 MoveGroup。
- 修改参数后运行进程仍然使用旧值。

## 22. 后续编写原则

- 按“准备 -> 安装 -> 标定 -> 验证 -> 运行 -> 排障”的复现顺序展开。
- 所有命令均应能够直接复制执行。
- 所有路径应使用工作区相对路径或明确的占位变量，避免绑定特定用户名。
- 每个有机械运动的步骤都要说明预期动作、通过标准和停止方法。
- 区分首次部署步骤、每次启动步骤和故障恢复步骤。
- 参数调整一次只改变一个变量，并保存调整前后的测量结果。
