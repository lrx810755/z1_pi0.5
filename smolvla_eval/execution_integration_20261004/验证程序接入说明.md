# 验证程序接入60 Hz插值与接触等待

## 默认入口

```bash
bash /home/lp531/ros2_ws/src/z1_ros2/scripts/run_smolvla_left_wrist_batch4_eval.sh --model pi05
```

原有菜单仍可使用。所有该菜单模型默认启用10 Hz动作点、60 Hz执行插值、闭爪后连续双指接触0.5秒才允许手臂移动、2秒内未达标则停止。PI0.5仍每次执行5个模型动作；chunk长度与模型权重未改变。

回到原执行方式做对照：

```bash
bash /home/lp531/ros2_ws/src/z1_ros2/scripts/run_smolvla_left_wrist_batch4_eval.sh --model pi05 --execution-rate 10 --prelift-contact-stable-s 0
```

## 实现与限制

- 模型动作每0.1秒一个，先对模型动作终点执行原有关节限位/.1 rad步长限制，再将动作段分为6个子步，每子步检查跟踪偏差、手指撞桌、停止请求与状态新鲜度。仿真时间调度；计算/消息延迟仍可能造成个别漏周期，不保证严格实时。
- 闭爪门控按实际阶段触发，不使用回放的固定12.1秒。等待中保持六个手臂关节目标，允许夹爪继续闭合；稳定后允许后续动作继续执行。若当前动作段要求手臂移动，等待期间暂停该动作段的进度、继续闭爪；稳定后从同一手臂插值点继续，不跳过抬升起点；夹爪保持等待期间已到达的闭合目标，避免回退开爪。记录prelift_waiting与policy_action_paused。普通动作段保持原时长，接触等待会额外延长执行时间，模型chunk的动作点数量不变。
- 接触连续性仅在ROS状态回调中更新，推理期间的接触中断也会清零。相邻遥测消息间隔超过新鲜度阈值亦清零；超时会记录prelift_contact_not_stable，遥测过期记录stale_grasp_status。
- 放置阶段按累计开爪变化识别释放，避免60 Hz每子步变化很小而漏识别开爪。
- 冻结时继续要求keep_collisions=True。解冻保留原场景两个tick的物理接触刷新流程，等待PHYSICS_READY后才发送下条动作；没有更改场景的物理配置。轨迹碰撞标志读取实际状态，不再硬编码为True。
- 新控制方案无法使几何上撞瓶的旧路径自动变得可行，也不能保证解决腕部遮挡。模型性能需单独验证。
